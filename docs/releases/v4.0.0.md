## v4.0.0: WebNN first

Media Clusterer now uses the most native AI hardware the browser offers: **WebNN** (NPU, then GPU, then CPU), then **WebGPU**, then the CPU. A setup wizard checks the device before anything downloads.

### ⚠️ Breaking change

On devices with WebNN (Chrome: `chrome://flags` → "WebNN API"), EmbeddingGemma 2 switches from the q4 WebGPU files to the fp16 WebNN files (up to 880 MB) under a new cache prefix, so embeddings cached by v3 there are recomputed once. The first visit now shows the setup wizard and downloads nothing until you start.

### What's new

- **WebNN backend for EmbeddingGemma 2**: each model part builds on the most native WebNN device that accepts it (NPU → GPU → CPU). On a Pixel 10 a photo embeds in about 3 s, where WebGPU on its PowerVR GPU took about 330 s and froze the phone. Photos of any shape, videos (as one clip of 4 frames) and text searches all run on it.
- **Setup wizard on first load**: checks WebGPU, WebNN devices, memory and Chrome AI, ranks the models for this device, pre-selects the one most likely to work and explains why. Return visits load the saved choice straight away.
- **Speed test page** (`npu-test.html`): the same model on WebNN NPU / GPU / CPU, WebGPU or WASM, with a copyable JSON report and its JSON Schema. Linked from the first-load card and the ⓘ dialog.
- **PowerVR GPUs** never run models on WebGPU any more, and the app no longer suggests the unsafe-WebGPU flag there.
- **Rewritten ⓘ dialog**: how it works, which AI runs where, privacy.
